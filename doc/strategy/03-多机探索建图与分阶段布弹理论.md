### 1.2 当前设计必须遵守的约束

- 各机只从合法传感器、公开状态和收到的消息获得信息。不能直接读取真实墙、真实机位或其他无人机实例的私有地图。
- 通信此前核对为两机距离严格小于 250 像素，双方通信器可用；墙体不参与该版本的通信遮挡判断。没有自动多跳转发，想经队友转发要在消息协议中实现。
- 你提供的赛事组消息是“初赛没有通信拒止区”。这可以简化初赛设计，**距离限制仍需处理**；以后其他阶段以对应配置为准。
- 炸弹库存属于各无人机。全队总库存充足，并不代表某一架机能负责所有目标。
- 放弹此前核对为动作从 0 变成 1 才触发；持续为 1 不会每步放一枚。库存不足、抓取状态不满足、与已有炸弹太近等情况会静默失败。
- 此前最小炸弹间距为 24 像素，本文记为 $d_{\min}$。不能把这个最小间距与评分用的覆盖半径混淆。
- 成功时炸弹由仿真器在实际机位生成。策略保存的目标坐标可能与实际位置有误差。
- 提交探索地图会立即结束当前回合。应先确认最后一次放弹成功，再发出提交。
- 红队没有蓝队那项返航健康得分，也没有为拿这项分而返回 ReturnArea 的必要；碰撞仍可能拖慢任务和造成损毁。
- 蓝队在原场景加载红队实际生成的炸弹布局。红队提交的墙图用于评分，不能据此认为蓝队直接获得这张地图。

多回合汇总此前发现 README 与本地 launcher 存在差异。做算法比较时保存每回合结果，统计平均值、低分结果和失败率；正式汇总方式以赛事平台说明为准。

## 2. 整体架构：一个阶段负责人，两套任务，共用导航

两位同学负责的是开发模块；正式运行时，每架无人机执行同一套策略，由自己的状态决定当前任务。

~~~text
每回合初始化
  └─ 创建各无人机的独立状态、地图和消息记录
      │
      ▼
阶段 A：EXPLORE，多机探索与同步建图
  每机观测 → 定位 → 本机建图 → 交换增量 → 融合已收到的地图
      ↑                                           │
      └──── 运动控制 ← 探索目标分配 ← 找前沿与估计新信息
      │
      ▼
阶段边界：SYNC_AND_PLAN
  停止领取探索目标 → 有限时间同步 → 确定地图快照
  → 刷新机位/库存 → 候选放弹点 → 联合选点、分配和排路线
      │
      ▼
阶段 B：PLACE，多机执行布弹
  分配的放弹目标 → 公共导航 → 到位并稳定
  → 放弹请求 → 下一步库存确认 → 广播放弹结果
  → 下一个放弹目标；失败则在已知地图中改派
      │
      ▼
阶段 C：SUBMIT
  核对放弹结果 → 整理融合墙图 → 指定一架机提交 → 回合结束
~~~

其中存在两个闭环：

1. 探索闭环：发现新墙、新空地会改变地图，从而改变下一探索目标。
2. 布弹执行闭环：实际机位、导航失败、库存和已放炸弹会改变剩余布弹任务。

第二个闭环不重新启动主动探索。布弹时仍读取传感器定位和避障，也可接收探索阶段迟到的消息，但不再为扩大地图覆盖派出探索任务。第一版按冻结的地图快照做战略选点，实时障碍信息只负责让执行安全、可行。

## 3. 评分决定优先级

### 3.1 红队总分

此前默认四项都是 0—100 分：

$$
S_{\text{red}}
=
0.50S_{\text{map}}
+
0.20S_{\text{bomb}}
+
0.20S_{\text{wall}}
+
0.10S_{\text{time}}.
$$

这说明：地图稳定性是系统基础；布弹需要同时照顾墙体覆盖、蓝队拆弹难度和完成时间。两个布弹分项各占 20%，不能只优化其中一个。

### 3.2 地图分不是“走过多少面积”

地图评分比较提交的二值墙图与真实墙体。此前实现对墙表面命中给予信用，对距离真实墙较远的误画施加处罚；它不是普通图像准确率，也不是只看空地覆盖率。

因此：

- 地图覆盖广，但墙整体错位，未必高分。
- 过度加粗、膨胀所有墙，可能新增错误预测。
- 无人机、炸弹、处置中心、返回区、干扰区不应全部画进“墙体提交层”。
- 空地、未知区和墙必须在内部地图分开保存；最终提交格式即使只表达墙，也不能反过来让内部地图只剩二值墙。

### 3.3 炸弹难度分

设某个有效参考蓝队得分为 $B_j$，难度为：

$$
D_j=\min\left(100,\max\left(0,2(100-B_j)\right)\right).
$$

设应放数量为 $K>0$，实际确认放置数量为 $k$，完成率为：

$$
c=\min\left(1,\max\left(0,\frac{k}{K}\right)\right).
$$

此前默认：

$$
S_{\text{bomb}}
=
c\cdot\frac{1}{m}\sum_{j=1}^{m}D_j.
$$

$m$ 为有效参考蓝队运行数量。配置也支持用中位数；有效参考数量不足时，评分状态可能仍为 partial，不能把此时的 0 或 pending 当作布局已证明没有难度。

例如蓝队得 80 分，难度是 40；放完库存，这项给红队总分贡献 8 分。蓝队得 50 分及以下时，难度已经饱和为 100。

蓝队分还包含处理炸弹、健康和效率。因此“路远”只是可能影响蓝队得分的因素，**不存在此前已核对出的‘离中心每远一米直接加几分’公式**。

### 3.4 墙体覆盖分

每枚炸弹在评分栅格上对应一个圆形范围。此前覆盖半径为：

$$
R_{\text{px}}
=
\operatorname{round}\left(\rho\min(H_{\text{px}},W_{\text{px}})\right),
\qquad \rho=0.12\ \text{为此前默认值}.
$$

这里 $H_{\text{px}},W_{\text{px}}$ 是评分用的像素栅格尺寸，不是我们自选的粗导航网格尺寸。导航每格代表多个像素时要先换算，不能直接对粗网格尺寸套公式。

所有圆形范围取并集，与真实墙体相交得到覆盖；同一墙像素不因多枚炸弹而重复加分。此前内部墙权重为 1，地图外框墙默认权重为 0.5。

覆盖分归一化为：

$$
S_{\text{wall}}
=
100\operatorname{clip}\left(
\frac{\text{加权墙体覆盖量}}{F_{\text{ref}}},0,1
\right).
$$

$F_{\text{ref}}$ 是评分器基于真实地图、固定应放数量及覆盖半径计算的确定性贪心基准。代码称其 theoretical optimum，但**算法上它是贪心基准，不能由这个名字推断已经求得严格全局最优**。同场景参考分母固定，布局更好的方向是增加实际覆盖分子。

这是一项评分计算。规划时不要据此把范围内的墙从导航地图删除，或假设炸弹一放下就炸开通路；红队、蓝队运动仍按场景实际机制处理。

### 3.5 时间分和真实运行时间

此前默认时间分使用仿真步。令 $r=t/T_{\max}$，$t$ 为回合结束步数，$T_{\max}$ 为步数上限，则：

$$
S_{\text{time}}
=
\begin{cases}
100, & 0\le r\le 0.5,\\
200(1-r), & 0.5<r<1,\\
0, & r\ge 1.
\end{cases}
$$

在总步数的一半以内完成，继续提早不增加这一项，但能提供容错余量。过了一半，再多耗一步就有时间分损失。

另有真实时间 walltime 上限，昂贵计算仍会导致提前结束。因此要同时维护仿真步预算与计算耗时预算。

## 4. 全系统的数据模型

### 4.1 每机独立保存什么

| 数据 | 内容 | 用途 |
| --- | --- | --- |
| 位姿 | 估计位置、朝向、时间戳、可信度 | 投影激光、导航、放弹误差判断 |
| 本机观测证据 | 自己看到的墙/空地及其来源、版本 | 可追踪、可更正的建图 |
| 本机融合地图 | 自己证据＋收到的队友证据 | 选探索目标、阶段边界形成快照 |
| 队友状态 | 最近收到的位置、库存、目标、阶段、时间戳 | 多机分工，判断信息是否过期 |
| 探索任务记录 | 前沿编号、认领者、期限、失败次数 | 减少重复，处理任务释放 |
| 布弹任务记录 | 候选点、执行者、顺序、状态 | 防止重复布弹、管理库存 |
| 已放炸弹记录 | 唯一事件编号、估计位置、误差、确认来源 | 扣库存、间距检查、剩余覆盖 |
| 阶段记录 | 阶段编号、快照版本、截止时间 | 统一切换，避免有人先提交 |

“全图”表示覆盖整个已知地图范围的数组或子图集合，并不代表对真实环境已全知。通信断开时，每机副本可能不同。

### 4.2 同一地图要有三种表达

**物理墙图**：保存实际墙的观测和可信度，用于提交和墙体覆盖估计。不要混入导航膨胀。

**导航代价图**：从墙图派生，按机身半径和定位误差膨胀障碍，区分可走、未知、危险，并叠加附近无人机、炸弹等临时障碍。

**区域/拓扑图**：把房间、走廊、门口和分支抽象成节点、边，用来理解探索分区和蓝队搬运路程。它是规划辅助表达，不取代精细导航网格。

三者应记录统一坐标定义：原点、轴向、单位、分辨率、行列顺序。数组的第一个索引通常是行，不等于世界坐标 $x$。

## 5. 阶段 A：多机探索与建图

### 5.1 定位是建图的前提

第一版优先使用合法 GPS 和罗盘测量，里程计做连续运动估计；GPS 暂时不可用时，里程计短时接续。需要更稳时加入激光扫描匹配和滤波。

无人机位姿为 $(x,y,\theta)$；激光一束距离为 $r$，相对机体方向为 $\phi$，则端点投影为：

$$
x_e=x+r\cos(\theta+\phi),\qquad
y_e=y+r\sin(\theta+\phi).
$$

定位误差会使所有激光端点一起错位。多机地图出现双层墙时，应先排查坐标和位姿，再调整地图融合权重。

第一版是 GPS 辅助的多机栅格建图与探索。只有真正联合估计轨迹、地图和跨机相对关系时，才更接近完整协同 SLAM；不需要为了名称而一开始加入复杂位姿图。[协同 SLAM 综述](https://arxiv.org/abs/2108.08325)

### 5.2 占据栅格与墙体类别分开

每格占据概率为 $p(c)$，用 log-odds 保存：

$$
L(c)=\log\frac{p(c)}{1-p(c)},\qquad
p(c)=\frac{1}{1+\exp(-L(c))}.
$$

$L>0$ 更倾向被占据，$L<0$ 更倾向空闲，$L=0$ 对应 0.5 的不确定状态。clip 是把更新后的数值限制在上下界内，避免一次结论强到无法纠正。

在逆传感器模型和独立性近似下，一般更新写为：

$$
L_t(c)=\operatorname{clip}\left(
L_{t-1}(c)+\ell(c\mid z_t)-L_0(c),
L_{\min},L_{\max}
\right).
$$

$\ell(c\mid z_t)$ 为本次测量对应的 log-odds，$L_0$ 是先验。先验为 0.5 时 $L_0=0$，才可直接使用常见的正/负固定增量。

处理一束激光时，射线到命中点前的格子提供空闲证据；有效命中端点提供占据证据。达到最大量程的“未命中”读数不能在最远端凭空画墙。

**占据不等于墙**：无人机、炸弹等也可能产生命中。墙体提交层应结合可用的语义信息、时间持续性和几何一致性判断；语义传感器不是自动给出完整墙地图的接口。误把队友留下的端点画成墙，会影响提交与路线。

### 5.3 多机地图融合的三个问题

1. **坐标对齐**：各机使用同一公开坐标系，或者估计局部图之间的变换。合法 GPS 在共同坐标系下能简化初始对齐，仍有噪声。
2. **证据去重**：一条观测被转发多次，只算一次。
3. **更正传播**：某机修正了位姿或子图，其他机应更新旧贡献，不能把“旧墙＋新墙”都留下。

推荐按“来源无人机、来源版本、地图块”保存贡献：

- 消息携带原始来源编号和版本；转发时保留来源。
- 新版本替换同一来源的旧版本。
- 融合时不要把对方已经融合过的整张图当作一份新的独立传感器证据叠加。
- 相同来源去重仍不消除不同机器观测之间的相关性，必要时限制置信度或保守融合。

成熟的地图合并项目也区分已知初始位姿与未知位姿：后者需足够重叠的地图特征才能可靠估计变换。[m-explore 地图合并说明](https://raw.githubusercontent.com/hrnr/m-explore/noetic-devel/map_merge/doc/wiki_doc.txt)

### 5.4 探索目标来自前沿

Frontier 是已知空地与未知区的边界。把相邻前沿格聚成簇，并在**可到达的已知空地**选择观察位姿。前沿本身可能在未知格内，不能直接要求无人机穿过未知障碍到质心。

每个候选探索任务包含：

- 可到达的观察位置和必要朝向；
- 预计可看到的未知区域；
- 预计能补充的墙体观测；
- 行驶和扫描时间；
- 定位、碰撞及通信风险。

这继承了经典前沿探索思想。[Yamauchi，1997](https://www.cs.cmu.edu/~motionplanning/papers/sbp_papers/integrated1/yamauchi_frontiers.pdf)

### 5.5 探索效用：信息价值必须减去路程和重复

定义探索候选位姿为 $g$，无人机为 $i$。本方案使用：

$$
U_i(g)=
a\widetilde I(g)
+a_w\widetilde I_{\text{wall}}(g)
-b\widetilde T_i(g)
-c\widetilde O_i(g)
-d\widetilde R_i(g)
-e\widetilde C_i(g).
$$

波浪号表示先归一化再组合：

| 符号 | 含义 |
| --- | --- |
| $I$ | 预计新增可观测信息 |
| $I_{\text{wall}}$ | 预计改善墙体完整性/准确度的信息 |
| $T_i$ | 沿可行路径移动并观察的时间 |
| $O_i$ | 与队友正在执行的任务的观测重叠 |
| $R_i$ | 定位、碰撞或卡住风险 |
| $C_i$ | 通信不同步可能造成的成本 |

这是本方案的启发式，不是官方公式或对某篇论文公式的照搬。墙图占 50%，所以除了未知空地，也要关注墙缺口、单侧可见的拐角和低可信度墙段。

信息增益的理论表达可用二元熵：

$$
H(p)=-p\log p-(1-p)\log(1-p).
$$

候选位姿的增益近似为可见格子的预期熵下降：

$$
I(g)\approx
\sum_{c\in V(g)}
\left[H(p_c)-\mathbb E\big[H(p_c\mid z_g)\big]\right].
$$

$V(g)$ 应考虑量程、视角和已知墙遮挡。第一版可用“能看到的未知格数量”近似，不能把圆形量程内所有格都当作一定可见。熵只是度量不确定性；不等于官方地图分。

### 5.6 多机探索分工：先分区域，再选区域内前沿

单纯“每机选最近前沿”容易让同一走廊挤满无人机。推荐两层决策：

- 上层把已知环境分成走廊分支或房间，分配主要责任区域。
- 下层在自己的区域选择信息价值高的前沿。
- 分区是偏好，不是永久禁区；本区完成或走不通，可释放责任并接其他区任务。

对环境结构进行分段再协调探索，已有研究可参考；这里只借用这个思路，不要求第一版实现完整论文系统。[Wurm、Stachniss、Burgard，2008](https://www.ipb.uni-bonn.de/wp-content/papercite-data/pdf/wurm08iros.pdf)

对于一次任务分配，令 $x_{ig}\in\{0,1\}$ 表示机 $i$ 领取目标 $g$：

$$
\max\sum_{i,g}x_{ig}U_i(g),
\quad
\sum_gx_{ig}\le1,\quad
\sum_ix_{ig}\le1.
$$

固定效用矩阵时，可以贪心或用线性分配求解。匹配只优化当前这一轮；不会自动得到全程最优。两个不同目标也可能观测高度重叠，因此“每目标最多一架机”还不够：选定一个目标后要降低周围目标的新增信息价值。

把目标价值、路径成本和已分配区域的重复信息共同考虑，是经典多机协调探索的依据。[Burgard 等，2005](https://www.ipb.uni-bonn.de/wp-content/papercite-data/pdf/burgard05tro.pdf)

### 5.7 通信有限时如何继续

推荐第一版采用“区域责任保底＋通信可达时协商”，而不是要求所有机器每步都接受远端协调者指令。

任务认领消息包含任务编号、认领机、预计到达时间、阶段编号、有效期。冲突时按既定的效用、认领版本和编号规则解决。切换任务加入保持时间和最小收益提升门槛，避免来回换目标。

超距失联后：

1. 按本机地图和最近有效任务继续；
2. 把队友信息逐渐标记过期，不当作实时机位；
3. 优先自己负责的区域；
4. 恢复通信后交换增量，消除重复任务。

没有消息不代表无人机死亡。永久分区通信下，不可能只靠未收到的消息保证全队始终无冲突。使用保底分区是为了减少冲突概率，不是给出绝对保证。

拍卖/共识方法如 CBBA 可作后续参考；其收敛结论有评分与通信条件，不能直接套到长期断联的竞赛系统。[Choi、Brunet、How，2009](https://dspace.mit.edu/entities/publication/b0bf0a05-be3b-433b-9f4b-ce314ed5178b)

### 5.8 防止多机探索反而更慢

多机效率受最后一架机、狭窄通道和重复劳动限制，不会简单等于单机时间除以机数。

第一版需要有三类保护：

1. **拥堵保护**：同一窄门附近不要同时派多架机；设置短期通行优先级，其他机等待或选别的目标。
2. **任务保持**：不因效用微小变化每步改目标；只有到达、地图显著变化、失效或更优收益超过门槛时重派。
3. **计算节流**：传感器和安全控制保持实时；地图块融合、前沿重建和全队分配按变化事件或较低频率执行。

允许可到达任务数少于无人机数。没有有价值任务的机可以暂时等待、协助通信或观察已有低可信度墙段，不要为了“所有机都在动”制造拥堵和无效路程。

### 5.9 共同导航负责把目标变成动作

公共导航模块接收一个世界坐标目标，不关心它是观察点还是放弹点。

路径层采用 A* 或其他栅格搜索，障碍按机身半径和误差膨胀；对角移动时检查是否切墙角。控制层根据路径点、机位、朝向和雷达做反馈控制、局部避障和脱困。

全局寻路回答“绕哪条路”，控制回答“这一仿真步怎样施加动作”。PD/PID 是第一版可选控制器；MPC 等方法可后续比较。这里没有必须先做强化学习的环节。

## 6. 什么时候结束探索

### 6.1 “完整地图”是工程目标，不能用真值判断

运行时不知道真实地图有多少可达空地，所以不能计算“已探索真实可达面积比例”作为在线停止条件；那是离线评估指标。

在线停止依据应组合：

- 各机已知可达区域内没有高价值前沿；
- 地图新增信息和墙图改进连续一段时间很少；
- 当前剩余前沿已被确认不可达、极低价值或多次失败；
- 最近收到的队友探索报告大致一致；
- 或达到必须为布弹保留时间的截止点。

“我没有前沿”只说明本机当前认知，不能立即代表全队探索完成。保留未知区也比编造墙和空地可靠。

### 6.2 为布弹预留预算

设当前步数为 $t$，剩余布弹路线的估计最长完成时间为 $\widehat T_{\text{place}}$，同步、规划、提交和容错预算分别为 $T_{\text{sync}},T_{\text{plan}},T_{\text{submit}},T_{\text{margin}}$：

$$
t+
T_{\text{sync}}
+T_{\text{plan}}
+\widehat T_{\text{place}}
+T_{\text{submit}}
+T_{\text{margin}}
\le T_{\max}.
$$

阶段边界采用“探索完成判据满足，或预留预算即将不足，二者先到者”。

第一版可以先用离线测试设定保守探索截止步数；尚未探索的地图不允许假装已知。可以估计放弹所需的预算，但不在探索阶段据此提前实际放弹。

### 6.3 同步与切换协议

建议明确区分“停止探索”“形成快照”“允许布弹”三个事件：

1. 每机报告探索状态和自己的地图贡献版本。
2. 宣布探索截止步数 $t_e$；到期后无人机停止领取探索任务。
3. 在有限同步窗口交换遗漏块、版本表和队友状态。
4. 发布快照版本和布弹开始步数 $t_p$，且 $t_p>t_e$。
5. 各机在 $t_p$ 后执行布弹计划；超时未同步者进入预定的本地保底流程。

共同截止时刻和阶段编号可以减少“有人还探图、有人先放弹”的情况。无法保证所有机器始终同步时，应保证至少在共同硬截止后才允许布弹，不无限等消息。

协调者可以临时由编号较小的可达机器担任；编号不需要修改。通信分区下可能出现多个协调者，因此应在协议里区分分区和阶段版本，而不是以为任命一个领导者就天然拥有全图。

### 6.4 不能只宣布同步，还要让通信真正可达

地图探索范围可能大于通信范围。若各机在不同地图角落停住，再等“收到完整地图”，这个等待可能永远不会结束。

阶段边界应包含通信接触计划：

- 在探索阶段记录合法已知、可达的汇合位置，如共同走过的入口附近；不要读取隐藏出生点或假设所有出生点相同。
- 进入同步阶段后，地图持有者沿已知安全路线靠近汇合位置。这个动作是传递成果，不是继续主动探图。
- 可以让相邻机器逐次接触交换，或维持已知的短链进行应用层转发；链路每一跳都要满足实际通信条件。
- 转发消息保留原始来源与版本，避免环路使同一地图反复被当作新证据。
- 以“收到哪些来源的哪个版本”为同步依据；知道有五架机不等于已收到五份地图。
- 同步时间预算必须包含到汇合位置的行驶时间和数据传递时间。代价太大时按截止执行保底，不要求所有机器跑回同一地点。

同步充分后可以再次分散布弹。应比较“汇合多耗的时间”与“全图提高地图分和布弹质量的价值”。第一版先采用容易验证的有限汇合窗口，后续再优化接触计划。

若无法在合法通信内取得队友的观测，最终提交者只能使用自己实际收到的融合图。不能用进程全局变量在阶段切换时瞬间补齐失联机器的地图。

## 7. 阶段边界必须交付什么

用于布弹的地图快照至少包括：

| 信息 | 要求 |
| --- | --- |
| 坐标元数据 | 世界原点、轴向、单位、分辨率和行列转换 |
| 已知空地、未知区、占据区 | 分开表达；未知不能默认可走 |
| 墙体估计 | 物理墙位置、可信度、来源/版本 |
| 导航可达性 | 各机到候选区域的路径是否存在 |
| 区域结构 | 可选的房间、分支、门口和连通关系 |
| 处置中心 | 合法传感器/公开接口获得的位置及可信度；未发现则标未知 |
| 每机状态 | 当前位置、朝向、库存、是否可用、数据时间戳 |
| 时间 | 当前步数、各阶段预算和最终提交截止 |

快照冻结的是战略规划依据；无人机位置必须在开始布弹时刷新。队友机位过期时要加误差余量，不能用他几十秒前的位置作为准确分配起点。

如果 GPS 后续修正导致墙图坐标变化，需要说明快照坐标是否随之修正。不能让墙图用旧坐标、机位用新坐标，却不做变换。

## 8. 布弹首先解决三个相互关联的问题

**选址**：选哪些点，才能提高墙体覆盖与蓝队难度？

**分配**：哪些机器有库存、可到达，并适合负责这些点？

**排序**：每架机以什么顺序放完，才能避免某机最后走极长路线？

这些问题相互影响。高价值点可能只有库存不足的机器能及时到达，因此不能先选出一批抽象“最好点”，再忽视执行困难。

设候选集为 $\mathcal C$，已选集合为 $S$，无人机 $i$ 的目标序列为 $\pi_i$，库存为 $b_i$。基本约束为：

$$
|S|\le K,\qquad
|\pi_i|\le b_i,\qquad
\bigcup_i\pi_i=S.
$$

每个目标只分配给一架机；目标必须可达、满足间距、能在时间内完成。已不可用机器的剩余库存不能作为可执行资源。

优先级建议：

1. 能正常完成并提交。
2. 在可执行时间内尽量放足库存。
3. 增加尚未覆盖的加权墙体。
4. 在前三项可靠后，提高经验证的蓝队难度。

这不是说永远必须放完才结束：若最后一枚需巨大绕行，要比较新增分和时间损失，见第 12 节。

## 9. 布弹理论一：加权最大覆盖

### 9.1 为什么不能每枚都选“墙最多的点”

设 $\mathcal W$ 是我们地图中估计的墙格集合，$w_q$ 是墙格 $q$ 的价值权重，$a(q)$ 是墙体可信度。候选点 $p$ 的圆形范围覆盖集合为：

$$
A(p)=\{q\in\mathcal W:\|q-p\|_2\le R\}.
$$

一组炸弹的覆盖价值为：

$$
F(S)=
\sum_{q\in\mathcal W}
w_q a(q)
\mathbf1\left(q\in\bigcup_{p\in S}A(p)\right).
$$

$\mathbf1$ 是条件成立取 1、否则取 0 的指示函数；并集确保同一墙格只计一次。内部墙与外框墙权重应按评分机制区分；判断不可靠时保留这种不确定性，而不是把所有连接到外框的内墙都武断降权。

新增一枚的边际收益为：

$$
\Delta F(p\mid S)
=
F(S\cup\{p\})-F(S).
$$

比如两个点各能覆盖 100 单位墙，但重叠 90；第二枚放在那里只新增 10。另一个点覆盖 70 且不重叠，新增就是 70，更值得考虑。

### 9.2 为什么贪心有理论依据

在固定候选点和固定、非负墙权重下，加权覆盖具有：

- 单调性：增加炸弹不会减少覆盖；
- 边际收益递减：已经覆盖越多，再放一枚可新增的墙通常越少，这叫次模性。

对于**只有“最多选 $K$ 个点”约束**的这种最大化问题，按边际收益选择的贪心有经典近似保证：

$$
F(S_{\text{greedy}})
\ge
(1-1/e)F(S^\star)
\approx0.632F(S^\star).
$$

这里 $S^\star$ 是同一候选集上的覆盖最优解。加入最小间距、路线时间、每机库存、失败概率、蓝队难度等约束后，不能再直接宣称整套方案仍有这个保证；这条结论只解释为什么覆盖子问题适合从边际贪心起步。[Nemhauser、Wolsey、Fisher，1978](https://link.springer.com/article/10.1007/BF01588971)

### 9.3 候选点怎样生成

从已知可达空地内采样，再保留不同类型的代表点：

| 类型 | 理论价值 | 需要检查 |
| --- | --- | --- |
| 多段内部墙附近 | 一枚范围可覆盖多段墙 | 墙是否真实，是否有足够机身空间 |
| 拐角、房间交界附近 | 覆盖不同方向的墙 | 可达性、定位误差、通道安全 |
| 深分支、绕路远的房间 | 可能提高蓝队搜索/搬运成本 | 对蓝队有效与否需实测 |
| 各无人机当前位置附近 | 放置耗时小，可作备用 | 间距、重复覆盖、实际机位 |
| 高价值点周围不同位置 | 对误差和被占用提供替代 | 替代点是否仍有收益 |

先粗采样、筛去不可达和间距不合格点，再对高价值区域细化。没有必要每步在全图每个像素计算一次布局。

候选点要求已知空地连通可达，不用未知区域里的“猜测好点”。评分圆形范围不要求我们观测到范围内所有墙；但未知墙的收益不能当成确定收益。

### 9.4 对定位和建图误差做稳健处理

本机放弹位置误差尺度为 $\epsilon_i$，队友炸弹记录误差为 $\epsilon_j$，保守间距为：

$$
\|\widehat p_i-\widehat p_j\|_2
\ge d_{\min}+\epsilon_i+\epsilon_j.
$$

这只在误差界有效时提供保守保证。若使用“若干倍标准差”，表达的是概率置信程度，不是绝对误差界。

评分覆盖也可使用保守半径：

$$
R_{\text{safe}}=\max(0,R-\epsilon_{\text{pose}}-\epsilon_{\text{wall}}).
$$

它让规划偏向位置误差下仍能覆盖的墙。实际评分仍使用官方 $R$，不能把规划余量写成评分规则。

## 10. 布弹理论二：增加蓝队工作量的代理模型

### 10.1 真正要优化的是蓝队运行后的结果

理论上，已知蓝队策略分布 $\mathcal B$ 时可考虑：

$$
\max_S\,
\mathbb E_{\beta\sim\mathcal B}
\left[D\big(B_\beta(S)\big)\right].
$$

$B_\beta(S)$ 表示蓝队策略 $\beta$ 在布局 $S$ 上的实际得分。对手策略、出生点、感知和协调方式不全知，因此运行时无法准确直接计算这个目标。

第一版用几何与任务成本作代理，再用多个蓝队基线校准。以下指标全部是**本方案的估计指标，不是官方直接加分项**。

### 10.2 地图上的路径距离比直线距离有意义

设处置中心为 $d$，已知导航图上的最短路径距离为 $d_G(p,d)$。隔墙两点直线很近，实际可能需要长绕行。

若蓝队一次只能运一枚，且每次从中心出发抓取再返回，理想化单弹工作量近似：

$$
C_{\text{transport}}(p)\approx2d_G(p,d).
$$

第一次可能从出生点出发；抓取接触点、携弹体积、载荷速度和障碍会改变距离与时间，因此这个式子只解释远端弹可能增加搬运工作量。

所有炸弹的粗总工作量为：

$$
W_{\text{blue}}(S)
=
\sum_{p\in S}
\left(2d_G(p,d)/v_{\text{carry}}+\tau_{\text{service}}\right).
$$

$v_{\text{carry}}$ 为理想化有效载荷速度，$\tau_{\text{service}}$ 为抓取/投递处理耗时。$W_{\text{blue}}/n_B$ 只能作为均匀分摊工作量的时间尺度或简化下界参考；真实并行完成时间还受任务分配、路径冲突和起点影响。

**不知道中心位置时**，不能读取真实地图补齐。可以暂时不用中心相关项，或针对合法已知的可能位置做保守估计。

### 10.3 搜索难度、分支结构和多机并行

另可考虑：

- 到达偏僻分支要经过多少路径；
- 是否需要进入不同房间才能看到炸弹；
- 多枚炸弹是否聚在同一容易被发现的区域；
- 对手是否能让多架机平行处理这些位置；
- 抓取和携弹是否需要穿过狭窄但实际可行的通道。

“分散”不是无条件更难：多分支会提高覆盖搜索成本，也可能让蓝队更容易并行分工。同一深分支放多枚有利于降低红队路程，但蓝队发现第一枚后更容易知道附近还有弹。

若要显式描述不同区域的边际价值，可用区域饱和函数：

$$
H_{\text{region}}(S)
=
\sum_r \omega_r\left(1-e^{-n_r(S)}\right),
$$

$n_r(S)$ 为区域 $r$ 中炸弹数，$\omega_r$ 为该区域的估计搜索价值。这个人为设计鼓励布局跨区、避免一处堆很多弹；它是否提高官方难度须靠蓝队实验决定，不能只看公式合理。

### 10.4 狭窄通道和墙体覆盖不等于能制造绝对封锁

在正常可达空地内布弹，避免把“让蓝队必须穿墙”“永久堵死全部通路”作为未经规则验证的假设。

蓝队可以抓取和运送炸弹；当前红队放置阶段明确忽略无人机与已放炸弹的碰撞。不能据此假设两阶段碰撞完全相同。几何拥挤也不是可靠的官方难度来源，应通过蓝队实际运行验证。

### 10.5 最低成本的验证办法

至少比较不同风格的本地蓝队：

1. 近距离优先、抓取后回中心；
2. 全图搜索再分配；
3. 有多机分工或不同搜索顺序的版本。

参考蓝队集合由赛事配置选择；自建基线只是研发工具。不要把某个示例蓝队的代码缺陷当成普遍策略优势，也不要把蓝队运行崩溃当作高难度——此前评分器排除了失败的参考运行。

## 11. 布弹理论三：选点与多机路线联合求解

### 11.1 从分数角度组合，不把不同单位随意相加

若有经实验校准的预测分数，可写：

$$
\widehat J(S,\pi)
=
0.20\widehat S_{\text{wall}}(S)
+
0.20\widehat S_{\text{bomb}}(S)
+
0.10\widehat S_{\text{time}}(T(\pi)).
$$

地图项在这个阶段暂视为固定。未知官方覆盖归一化分母时，只能构造相对代理；不能声称自己预测出准确分数。

第一版可使用可解释的增量效用：

$$
V_i(p\mid S,\pi_i)
=
\alpha\widetilde{\Delta F}(p\mid S)
+
\beta\widetilde{\Delta H}(p\mid S)
-
\gamma\widetilde{\Delta T_i}(p)
-
\eta\widetilde{\mathcal R_i}(p).
$$

$\Delta H$ 是蓝队工作量代理的边际变化，$\Delta T_i$ 是把该点加入机 $i$ 的当前路线所增加的耗时，$\mathcal R_i$ 是执行失败风险。

先归一化各项，再调权重。可以先令 $\beta=0$ 建立墙覆盖和可执行路线基线；随后加入蓝队代理，判断它有没有提升实际难度。

### 11.2 用路线插入成本，不能只看“机到点的距离”

设机 $i$ 原路线相邻目标为 $a,b$，在它们之间插入新点 $p$，新增路程为：

$$
\Delta L_i(p)=d_G(a,p)+d_G(p,b)-d_G(a,b).
$$

路线末尾插入则只计从末尾到新点的距离。无人机起点是**阶段切换时的当前位置**；红队没有强制回出生点要求，因此不要无故给路线加回仓库边。

加入放弹稳定与确认耗时：

$$
\widehat T_i(\pi_i)
=
\sum_{(a,b)\in\pi_i}\widehat\tau_i(a,b)
+
|\pi_i|\tau_{\text{place}}
+
T_{i,\text{reserve}}.
$$

这里路线包含从当前起点出发的第一段，$\widehat\tau_i$ 应由实际导航测试校准，不能只用理想最大速度。

并行放弹完成时间为：

$$
T_{\text{place}}\approx\max_i\widehat T_i(\pi_i).
$$

因此要避免总路程不长却某一架机特别忙。多车辆路径问题中的“缩短最长路线”与此对应；参考工程工具是 OR-Tools，不表示它能直接替我们求出带未知地图和通信限制的竞赛最优策略。[OR-Tools 多车路径说明](https://developers.google.com/optimization/routing/vrp)

### 11.3 推荐第一版的联合贪心

在阶段边界按下面顺序生成计划：

1. 为所有候选点估计墙覆盖集合、蓝队代理特征和可达性。
2. 对每个“有库存无人机—候选点—路线插入位置”组合计算增量效用。
3. 过滤超时、不可达、间距不合格以及与既有任务冲突的组合。
4. 选当前可行组合，更新该机库存预算和路线、全队覆盖并集、间距约束。
5. 对更新后的状态重算边际收益，继续选择。
6. 做少量点替换和跨机任务交换，减小最长路线或提高覆盖。
7. 限制规划耗时，保留当前最好的可执行方案作为结果。

每次都更新并集，避免把同一面墙当作“新收益”卖给多架机。联合贪心没有整套问题的全局最优保证，但便于解释和调试。

布弹点已固定时，单步匹配可分配每机的下一目标；每机负责多个点时则涉及序列与路线，不能把一次 Hungarian 匹配视为解决了全部路线问题。

## 12. 时间紧张时如何取舍

### 12.1 放足库存的价值

难度平均值为 $\bar D$ 时，多成功放一枚，对难度分贡献的直接变化近似为：

$$
\Delta S_{\text{bomb}}\approx\bar D/K.
$$

这是把布局变化对蓝队难度的影响暂忽略后的估计；实际 $\bar D$ 也可能变化。漏放还会降低墙体覆盖，并且其评分基准分母此前使用固定应放数，不能用少放炸弹换一个更小参考分母。

所以第一版应优先用可靠、可达的备选点完成库存，少在最后追逐极远的高价值点。

### 12.2 多走一步是否值得

超过半程但尚未超时，按此前默认权重，时间项对红队总分的损失约为：

$$
\Delta S_{\text{red,time}}
=
-20\frac{\Delta t}{T_{\max}}.
$$

是否继续去最后一处，可比较：

$$
0.20\Delta\widehat S_{\text{wall}}
+
0.20\Delta\widehat S_{\text{bomb}}
>
20\frac{\Delta t}{T_{\max}}
+\text{执行风险代价}.
$$

这是辅助决策，不是准确分数承诺。第一版采用清晰的最终截止：预算不足就选择近处合格点；仍无法完成时，保存已确认结果并按时提交有效地图。

### 12.3 不应为了全队一致无限等待

消息超过有效期，状态标记为“未知”，不能把未确认的放弹算成功，也不能等到超时才处理。

硬截止前保留提交窗口：持有合法融合墙图的可用无人机能完成提交，即使有队友仍缺少确认。提交提前结束队友动作，因此这个条件要写进所有无人机的共同规则。

## 13. 阶段 B：可靠执行布弹

### 13.1 每枚炸弹的状态机

~~~text
未分配
  → 已认领
  → 正在导航
  → 到达并稳定
  → 发出一次放弹请求
  → 等待下一步库存变化
      ├─ 库存确实减少 → 已确认 → 广播 → 执行下一目标
      └─ 未减少 → 分析失败条件 → 复位动作 → 有限重试/换点/释放任务
~~~

“到目标了”“发过指令了”“库存减少了”是三个不同事实。

到位判据包含距离误差、机位可信度和运动速度；只检查与目标的距离可能导致经过目标时高速放下，实际炸弹偏离计划。

### 13.2 放弹失败的处理

| 情况 | 处理 |
| --- | --- |
| 动作一直维持为 1 | 先回到 0，再准备下一次上升沿 |
| 抓取器状态妨碍布弹 | 按规则关闭抓取、确认状态 |
| 点位离已有炸弹太近 | 选择满足稳健间距的附近替代点 |
| 导航不可达/卡住 | 在已知地图内重规划，超过重试限就改派 |
| 库存和任务数量不匹配 | 以实际可读库存更新计划 |
| 队友记录过期 | 降低信任、增加余量，按预定区域保底 |
| 无人机损毁或不可用 | 释放目标；库存不自动转移给别的机 |

确认后的记录保存执行者、放弹序号、确认步数和估计放置坐标。不允许为了得到精确记录调用隐藏真实位置；仿真器最终记录的实际炸弹坐标才用于评分。

### 13.3 当前红队阶段应忽略炸弹碰撞，仍需避让队友

2026-10-02 重读 `BombDeployer` 确认：新放炸弹设置 `ignore_drone_collisions=True`，红队无人机不会被自己的炸弹实体挡住。地图层仍要过滤炸弹命中；导航层可以忽略语义确认为炸弹的对应激光读数，但不能用这种过滤结果在建图中宣称炸弹后方已被观测为空地。

狭窄通道中仍可能因无人机之间的碰撞而拥堵。同步和报告阶段不要让所有机挤向同一个精确坐标，应在通信范围内选择彼此有间距的已知可达汇合点。蓝队阶段的搬运与碰撞机制应单独验证。

### 13.4 分区失联时的布弹保底

如果阶段边界仍没有共同全图，应诚实区分两种情况：

- 同步充分：按共同快照和协商计划执行。
- 同步不充分：各机只在自己的预分配区域、已知可达点布弹，尊重最近收到的任务和炸弹记录。

不要让多个通信分区各自把同一份“全队总库存”再计划一次。它们只能分配自己确认控制的机器及库存。

分区边界留间距缓冲，放弹前尽量获得附近队友记录；仍不能保证完全无重复，但仿真器的最小间距条件会拒绝不合格放置。失败后记录并改点，不反复无条件触发。

## 14. 两人协作：模块职责与交付信息

沿用已经同意的分工：**同学负责整个探索，包括探索目标规划；你负责地图完成后的布弹；两人共同维护运动模块，总入口由你集成。**

| 模块 | 主责 | 输入 | 输出 |
| --- | --- | --- | --- |
| Explorer：定位/建图/融合/探索协调 | 同学 | 本机观测、收到的合法消息、导航成本 | 地图快照、探索目标、探索结束报告 |
| Navigator：路径和运动控制 | 两人共管，每项修改指定一人主写 | 当前位姿、导航图、目标 | 路径成本、每步运动建议、到达/不可达/卡住状态 |
| BombPlanner：布弹选择与执行管理 | 你 | 融合地图、机位、库存、时间、导航成本、炸弹记录 | 各机放弹目标序列、一次放弹请求、确认记录 |
| PhaseCoordinator：阶段和提交 | 你集成，共同约定 | 探索报告、地图版本、放弹结果和预算 | 阶段编号、切换时刻、提交决定 |
| 消息协议 | 共同约定 | 地图贡献、任务、状态和事件 | 可去重、有版本、能判断过期的消息 |

总入口把当前阶段的目标交给 Navigator，并组装最终动作。每个仿真步只应有一个明确的运动目标，不能同时接受 Explorer 与 BombPlanner 各自写入推力。

这里是职责约定，不要求只能创建四个文件；数据类型、消息和地图工具可以另行拆分。接口的稳定性比文件数量更重要。

### 14.1 你需要向同学索取的最低交付

1. 一整张已融合地图快照，含空地、未知、墙和坐标元数据。
2. 地图版本、可信度、可用范围，以及哪些区域尚未知。
3. 当前探索是否完成、何时停止探索的报告。
4. 合法已发现的处置中心/区域信息，未知就标未知。
5. 可共用的“到任意已知目标的导航”和“估算路径成本”能力。

位姿、库存、时间通常由总入口从仿真器开放接口读取，再传给各模块，不一定要让 Explorer 包办。

### 14.2 你不需要向同学索取的东西

不要求他决定最终炸弹布局，也不要求他为每枚炸弹手写一条专用控制流程。双方共同导航处理指定坐标；你的模块负责选坐标、请求放弹、核实是否成功。

约定先用一张人工构造的地图和虚拟机位测试布弹决策。等真实探图快照准备好，替换数据来源，避免你一直等待整个 SLAM 完成才开始分析。

## 15. 一个贯穿示例

以下数字是教学假设，不是官方地图或评分参数。

### 15.1 探索分配

三架机面对 A、B、C 三个信息价值近似相同的前沿，路径成本为：

| 机号 | A | B | C |
| --- | ---: | ---: | ---: |
| 0 | 10 | 40 | 45 |
| 1 | 12 | 35 | 20 |
| 2 | 40 | 10 | 25 |

各自就近会让 0、1 都去 A。一次分配可以用 0→A、1→C、2→B，成本合计 40，覆盖三个方向。

它们移动中持续建图；交换来源明确的增量。后续 A、B、C 消失，说明这些前沿已被观测，但可能出现更深前沿。达到探索停止条件后，统一进入同步窗口。

### 15.2 地图冻结后的布弹候选

假设融合图给出六组内部墙 $w_1,\ldots,w_6$，各重 10。三架机每机一枚弹，候选点之间满足间距且都可达：

| 候选点 | 覆盖墙组 | 到中心的路径距离 |
| --- | --- | ---: |
| $p_A$ | $w_1,w_2,w_3$ | 20 |
| $p_B$ | $w_2,w_3,w_4$ | 50 |
| $p_C$ | $w_5,w_6$ | 70 |
| $p_D$ | $w_4,w_5$ | 45 |

先选 $p_A$，覆盖值 30。此时：

- $p_B$ 新增只有 $w_4$，值 10；
- $p_C$ 新增 $w_5,w_6$，值 20；
- $p_D$ 新增 $w_4,w_5$，值 20。

可先选 $p_C$，再从 $p_B,p_D$ 中选覆盖剩余 $w_4$ 的点。两种布局覆盖都为 60；这时红队路程、蓝队代理和执行风险才用于进一步比较。

### 15.3 看机位后选择执行方案

假设刷新机位后得到路径成本：

| 机号 | $p_A$ | $p_B$ | $p_C$ | $p_D$ |
| --- | ---: | ---: | ---: | ---: |
| 0 | 5 | 35 | 60 | 40 |
| 1 | 30 | 10 | 45 | 12 |
| 2 | 60 | 40 | 8 | 35 |

可以选 0→$p_A$、1→$p_B$、2→$p_C$。覆盖 60，各机路径成本为 5、10、8。

若改选 $p_D$，1 号成本为 12、蓝队搬运代理稍低；本例更偏向 $p_B$。但若实际 $p_B$ 通道定位不稳、预计会卡住，$p_D$ 可能是更可靠的替代。

每机到位后稳定、触发一次放弹，并在下一步确认库存变为 0。三份确认送达后，持有融合墙图的提交机结束回合。没有确认的目标仍属于“未成功”，不能为了让流程看起来完整而改成已完成。

### 15.4 这个例子体现的依赖关系

- 地图决定哪里有覆盖价值、哪里可达。
- 阶段切换后的机位决定谁负责最省时。
- 库存决定每机能接几个点。
- 已选覆盖并集决定下一枚真正新增多少。
- 蓝队难度代理用于比较，还须实际蓝队验证。
- 执行确认把“理论计划”变成“真实已放布局”。

## 16. 评价体系：每一层都要有自己的证据

### 16.1 探索和地图评价

| 指标 | 说明 |
| --- | --- |
| 官方地图分 | 主要验收指标，使用比赛对应评分器 |
| 墙定位误差、误画和漏画 | 看对比图，区分坐标错位与分类错误 |
| 已知可达范围增长 | 在线趋势，不称为真实完整覆盖率 |
| 达到目标地图质量所用时间 | 验证多机是否提高效率 |
| 重复观测/区域重复率 | 判断分工是否减少重复 |
| 队友地图差异和版本滞后 | 判断通信与融合是否可靠 |
| 导航失败、卡住、损毁 | 判断控制问题是否吞掉决策收益 |

离线研发可用真实地图计算覆盖率、IoU 或误差；这些真值不能进入参赛运行时的决策。

### 16.2 布弹评价

| 指标 | 说明 |
| --- | --- |
| 实际放置数/应放数 | 验证完成率 |
| 官方墙体覆盖分 | 不能只看我们自己的估计值 |
| 多参考蓝队实际难度分 | 验证蓝队代理是否真的有效 |
| 布弹阶段最长完成时间 | 多机执行是否平衡 |
| 静默失败次数与原因 | 验证间距、状态和动作边沿 |
| 目标点与估计实际放置点偏差 | 验证控制与定位 |
| 红队总分 | 判断单项提升是否值得耗时 |
| 平均、低分结果和失败率 | 判断布局与系统是否稳定 |

### 16.3 消融实验

一次只改变一层，建议先比较：

1. 多机独立探索；
2. 共享地图、各自选目标；
3. 共享地图＋区域/前沿任务协调；
4. 布弹就近且间距合法；
5. 布弹改为墙体边际覆盖＋库存/路线；
6. 再加入蓝队难度代理；
7. 再加入稳健误差余量、点替换和路线平衡。

在相同地图、可控初始状态/随机种子、无人机数、库存、时间预算和硬件下比较，多回合保存结果。五张公开地图用于开发，另留地图或自建变体检验泛化，不能在决策中按地图名称硬编码最佳炸弹坐标。

### 16.4 本地评估的正确边界

此前仓库有提交检查和比赛模式 launcher。提交检查验证格式和禁用接口，launcher 才实际运行策略。只跑红队通常得到地图、墙覆盖、时间等部分结果；参考蓝队难度需配套蓝队运行。

本文不列新的运行命令，避免把理论方案混成环境操作手册。具体执行以当前仓库文档和最新配置为准。

| E | 阶段切换与同步 | 无无限等待，不提前提交，不在探索时放弹 |
| F | 就近合法布弹 | 库存确认与实际放弹数一致 |
| G | 边际墙覆盖＋联合路线 | 官方覆盖改善，同时保持完成率 |
| H | 蓝队代理与稳健优化 | 多个蓝队/地图上有实际收益 |

你与同学可以并行：同学推进 B—D；你先用假地图推进 E—G 的理论和离线验证；A 与公共导航共同完成。第一版验收是整个闭环可靠，并不要求一次把表中所有优化做完。

## 19. 开发前共同确认的十项约定

1. 地图原点、轴向、单位、分辨率、行列顺序一致。
2. 物理墙层、导航障碍层、未知区分开。
3. 地图贡献能识别来源、版本、重复和更正。
4. 通信断开后仍能按本机合法信息运行。
5. 探索任务由同学模块负责，布弹目标由你的模块负责。
6. 两个阶段共用 Navigator，不直接各自写一套推力。
7. 探索停止、快照版本、布弹开始与提交截止都有明确规则。
8. 候选布弹点同时满足可达、间距、库存和时间条件。
9. 以库存变化确认放弹；未确认事件不算成功。
10. 评价使用官方分项＋执行指标，蓝队代理必须经对抗运行验证。

## 20. 符号与数学排版约定

| 符号 | 含义 |
| --- | --- |
| $i$ | 无人机编号 |
| $g$ | 探索观察位姿 |
| $p$ | 布弹候选坐标 |
| $S$ | 已选择/已确认炸弹位置集合，上下文注明 |

| $d_G$ | 地图中合法可行路径距离 |
| $d_{\min}$ | 炸弹最小间距 |
| $R,\rho$ | 评分覆盖半径、相对地图尺寸的半径比例 |
